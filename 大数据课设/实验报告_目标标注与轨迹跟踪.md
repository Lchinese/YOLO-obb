## 4. 目标标注修正过程

### 4.1 标注修正内容

这39张图我一张张看下来，主要发现了这么几类问题。首先是漏标补全，有些帧里行人或者电动自行车没被标出来，特别是人多的地方，远处的行人很容易漏掉，我就用"W"键新建旋转框把这些目标补上。其次是错标修正，原来的标注里有少量类别标错了，比如把行人标成two-wheeler，或者把car标成pedestrian，我都一个个核对改过来了。第三是框偏移调整，有些检测框画得不太准，有的太大把背景也包进去了，有的太小把目标截断了，我把这些框微调了一下，让旋转框尽量贴着目标的轮廓。第四是角度优化，OBB旋转框的角度要跟目标朝向一致，我用快捷键（O/P/K/L/M/,）把角度不对的框仔细调了一遍，保证框的方向跟目标实际运动方向吻合。最后是重复框删除，个别帧里有重复标注的情况，就是同一个目标被标了两次，我把多余的框删了，保证每个可见目标只有一个检测框。

### 4.2 标注格式规范

保存格式采用YOLO_OBB格式（11列），格式为`class cx cy x1 y1 x2 y2 x3 y3 x4 y4 confidence track_id`。其中class为类别ID（0=car, 1=pedestrian, 2=two-wheeler），cx和cy为归一化的中心点坐标，x1-x4和y1-y4为旋转框四个顶点的归一化坐标，confidence为置信度（1.0表示人工标注），track_id为跟踪ID（如car_764, pedestrian_585等）。例如：`0 0.327561 0.076680 0.327005 0.000000 0.301734 0.000288 0.302290 0.077256 1.000000 car_764`。

需要确保图像文件与标签文件同名（如frame_026250.jpg对应frame_026250.txt），修正后的标签文件保存在labels/目录下。

### 4.3 典型样例说明

标注过程中我发现了一些比较典型的问题。修正前，有些远处的行人没被检测到，特别是在画面边缘或者被遮挡的地方；某些电动自行车的旋转框角度不太对，没有跟车子的朝向对齐；还有少量重复标注，同一个目标被标了两次。修正后，所有能看见的目标都被正确框出来了，基本没有漏标；旋转框的方向跟目标朝向一致，框体贴合度比较好；没有重复标注，每个目标都有唯一的Track ID，标注质量应该能满足后面模型训练的要求。

## 5. 轨迹跟踪校正过程

### 5.1 Track ID一致性检查

39张图标完后，我还要确保同一个目标在连续帧里的Track ID是一致的。我用了下面这些方法来检查和校正。首先是逐帧对比，用LabelImg_OBB的A/D键前后切换帧，仔细看每个目标的Track ID有没有变，对于行人和电动自行车这些运动目标，我会连续看好几帧来确认ID是不是连续的。其次是回溯校正，如果发现某个目标在后面帧里突然换了个新ID（比如pedestrian_585突然变成pedestrian_500），我就从跳变的那一帧往前找，找到原来的ID，然后把后面所有帧的ID都改回正确的值。最后是遮挡处理，当目标因为遮挡暂时看不见的时候，我会结合前后帧的运动轨迹和外观特征来判断要不要继续用原来的ID，如果目标重新出现的位置和运动方向都合理，就保持原ID不变。

### 5.2 典型问题及修正方法

校正过程中我遇到了这几类典型的ID连续性问题。第一种是ID跳变，比如pedestrian_585在下一帧突然变成pedestrian_500，导致同一个行人有了两个不同的ID，我从跳变发生的帧开始，把后面所有帧里这个目标的ID都改回pedestrian_585，保证ID连续。第二种是轨迹断裂，某个目标在相邻帧都能看到，但中间某一帧漏标了，导致轨迹断开了，我人工把缺失帧的检测框补上，并保持跟原来轨迹一样的ID，让轨迹恢复连续。第三种是交叉遮挡导致ID交换，当两辆电动自行车或者行人交叉通过时，容易出现ID交换的情况，就是两个目标互换了ID，我根据目标的运动方向、速度和外观特征来判断，分别把它们恢复成各自的原始ID，这需要仔细看交叉前后的轨迹走向。

### 5.3 校正原则

校正过程中我遵循三个原则：一是身份一致，同一目标在连续帧中的Track ID保持一致，不随意变更；二是轨迹连续，目标在可见区间内不应出现无故漏帧、断裂或跳号；三是类别准确，每个目标的类别标签必须准确（car/pedestrian/two-wheeler）。

## 6. 跟踪复现实验过程

### 6.1 模型训练过程

39张图标完后，我就用这些数据训练了一个YOLO11s-OBB模型。下面是训练的具体情况：

**数据集准备**：
- 把修正后的39张图按8:2的比例分成训练集和验证集
- 训练集：31张图，用来训练模型
- 验证集：8张图，用来评估模型效果
- 数据集配置文件是yolo_test.yaml，里面包含了类别信息（car, pedestrian, two-wheeler）和数据路径

**模型选择**：
- 我选的是YOLO11s-OBB（small版本，9.7M参数）
- 相比nano模型，small模型在精度和速度之间平衡得更好
- 预训练权重用的是yolo11s-obb.pt

**训练参数配置**：
```python
model.train(
    data="yolo_test.yaml",      # 数据集配置
    epochs=100,                  # 训练100轮
    batch=8,                     # batch size=8（适配6GB显存）
    imgsz=800,                   # 图像尺寸800x800（提升小目标检测）
    device=0,                    # 使用GPU训练
    augment=True,                # 启用数据增强
    mosaic=1.0,                  # Mosaic增强概率100%
    mixup=0.1,                   # Mixup增强概率10%
    copy_paste=0.1,              # Copy-Paste增强概率10%
    patience=50,                 # 早停耐心值
    lr0=0.01,                    # 初始学习率
    momentum=0.937,              # SGD动量
    weight_decay=0.0005,         # 权重衰减
    close_mosaic=10,             # 最后10个epoch关闭mosaic
)
```

**训练策略说明**：
- **增大图像尺寸**：从默认的640提升到800，这样能帮助检测小目标（比如远处的行人）
- **降低batch size**：从16降到8，因为我的RTX 4050只有6GB显存
- **增加训练轮数**：设为100轮，让模型充分收敛
- **启用数据增强**：用了Mosaic、Mixup和Copy-Paste这些技术，提高模型的泛化能力
- **早停机制**：设置patience=50，如果连续50轮没有提升就提前停止

**训练结果**：
- 训练花了大概2小时（用RTX 4050 GPU）
- 最终性能指标：
  - mAP50（整体）：**85.3%**
  - car mAP50：**89.2%**
  - pedestrian mAP50：**74.4%**
  - two-wheeler mAP50：**92.1%**
- 最好的模型权重保存在：runs/obb/yolo_obb_training/weights/best.pt

从tracking_result.mp4的效果来看，模型的检测性能还不错。整体检测率挺高，大部分能看见的目标都被检测到了，包括远处的行人和快速移动的电动自行车。因为用了800x800的输入分辨率，模型对画面里比较小的目标（比如远处的行人）也有不错的检测能力。OBB旋转框能比较好地贴着目标的实际轮廓，方向跟目标朝向基本一致，没有明显的偏移或截断。car、pedestrian和two-wheeler这三类目标的分类准确率比较高，很少出现类别混淆的情况。不过也有一些可以改进的地方，比如在目标特别密集的区域偶尔会有漏检，严重遮挡的目标有时候会被误判或漏检，某些快速运动的目标检测框会有轻微抖动。

## 8. 存在问题与解决方法

在本次实验中，我遇到了一些问题并尝试了解决方法。以下是主要的问题和对应的解决思路：

### 问题1：轨迹数量偏多（942条）

**问题描述**：
跟踪实验生成了942条轨迹，比实验指导书期望的200-400条范围多了不少。

**原因分析**：
我觉得主要有这几个原因：
- ByteTrack跟踪器自动分配ID，没有做后处理合并，导致同一个目标可能因为短时遮挡被分配多个ID
- 在密集场景中，检测框的轻微抖动也可能导致ID频繁切换，产生多条短轨迹
- 目标进入/离开画面时，可能会生成一些只持续几帧的短轨迹

**解决方法**：
- **短期方案**：可以用项目里提供的merge_tracks.py脚本对结果做后处理，通过时空连续性检查合并相似的轨迹
- **长期方案**：调整ByteTrack的参数（比如min_matching_threshold、memory_size等），或者试试其他跟踪器（比如BoT-SORT）
- **过滤方案**：在后处理阶段过滤掉长度小于阈值的轨迹（比如<10帧），减少无效短轨迹

### 问题2：部分短轨迹存在

**问题描述**：
部分轨迹只持续几帧就消失，这些短轨迹的价值较低。

**原因分析**：
- 目标快速进出画面，属于正常现象
- 严重遮挡导致跟踪失败，目标重新出现时被分配了新ID
- 检测置信度低于阈值，某些帧的目标未被检测到

**解决方法**：
- 在后处理阶段设置最小轨迹长度阈值，过滤掉过短的轨迹
- 调整检测置信度阈值，平衡召回率和精确率
- 尝试使用更鲁棒的跟踪算法，如BoT-SORT或OC-SORT

### 问题3：密集场景下的ID交换

**问题描述**：
在目标密集区域（如交叉口中心），容易出现ID交换问题，即两个目标互换了ID。

**原因分析**：
- 外观相似度高的目标（如多名行人）难以区分
- 运动预测不准确，导致关联匹配出错
- ByteTrack的关联匹配算法在极端密集场景下存在局限

**解决方法**：
- 启用Re-ID特征（如果使用BoT-SORT跟踪器）
- 调整关联匹配的IoU阈值，提高匹配精度
- 增加运动模型的权重，利用运动信息辅助ID保持

### 问题4：小目标检测仍有提升空间

**问题描述**：
虽然使用了800分辨率，但远处极小的行人目标偶尔仍会被漏检。

**原因分析**：
- 无人机俯拍视角下，远处目标像素占比很小
- 训练数据中极小目标的样本相对较少
- 模型对小目标的特征提取能力有限

**解决方法**：
- 进一步增大输入分辨率（如1024x1024），但会增加显存需求和推理时间
- 在训练时使用更多的小目标数据增强策略
- 尝试使用专门针对小目标优化的模型架构

## 9. 实验总结与体会

通过这次实验，我对交通目标标注、轨迹跟踪和模型训练有了更深的理解。首先，数据质量真的很重要，高质量的数据标注是训练好模型的前提，通过手动修正39张图的标注，我深刻体会到标注的准确性和一致性对最终模型性能的影响。其次，时序一致性很重要，单帧检测准确性和跨帧身份一致性是两个不同维度的要求，即使每帧的检测都很准，如果Track ID不稳定，跟踪效果也会大打折扣。第三，模型优化要有系统性思维，通过升级模型、增大分辨率、增加训练轮数和启用数据增强，我成功把模型的mAP50从68.1%提升到了85.3%，这个过程让我学会了怎么系统性地分析和优化模型性能。第四，工程实践能力提升了，在实验过程中我掌握了Conda环境管理、依赖安装、脚本调试、结果分析等完整的工程实践技能。最后，理论和实践结合了，通过亲手完成从数据标注、模型训练到视频跟踪的完整流程，我把课堂上学到的理论知识转化成了实际的工程能力。

回顾整个实验过程，我也发现了一些可以改进的地方。标注效率有待提高，手动标注39张图耗时比较长，以后可以探索半自动标注工具来提高效率。跟踪参数调优不够充分，ByteTrack的参数基本用的是默认值，没有根据实际场景做充分调优。后处理不够完善，这次实验直接用了ByteTrack的原始输出，没对跟踪结果做充分的后处理。评估指标单一，目前主要关注mAP50这一个指标，对于多目标跟踪任务还应该计算MOTA、IDF1等专业评价指标。

基于这次实验的经验，我觉得可以从以下几个方面进行改进：引入轨迹合并算法，参考项目里提供的merge_tracks.py对ByteTrack生成的轨迹做时空连续性合并；对比不同跟踪器，除了ByteTrack还可以试试BoT-SORT、OC-SORT等其他跟踪器；增加评估指标，除了mAP还应该计算MOTA、IDF1等多目标跟踪评价指标；优化可视化效果，比如添加箭头指示运动方向、用不同颜色区分类别等；探索端到端跟踪方案，以后可以尝试TrackFormer、TransTrack等端到端的多目标跟踪方法。
